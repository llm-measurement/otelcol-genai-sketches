# Collector v0.3.1 and Helm Chart 0.3.3

This security update rebuilds the collector with Go 1.26.9 and
`golang.org/x/net` v0.60.0. Chart 0.3.3 selects collector v0.3.1 by default.

## Security Fixes

The update addresses HTTP/2 advisories **GO-2026-6603, GO-2026-6610,
GO-2026-6611, GO-2026-6612 and GO-2026-6617**, which are reachable in the
v0.3.0 distribution's source call graph. The collector's OTLP receivers use
HTTP and gRPC, so operators should upgrade even when they use only one transport.

Go 1.26.9 also fixes source-reachable standard-library advisories
**GO-2026-6599, GO-2026-6600, GO-2026-6605, GO-2026-6607, GO-2026-6608
and GO-2026-6613** in that distribution. Reachability is a static scan result;
exposure depends on the components and configuration in use.

Build tooling now uses `golang.org/x/mod` v0.41.0, including the fixes for
**GO-2026-6179 and GO-2026-6180** introduced in v0.40.0. This is a build-tool
dependency update, separate from the runtime receiver findings.

## Upgrade

- Image: `ghcr.io/llm-measurement/otelcol-genai-sketches:0.3.1`.
- Chart: `oci://ghcr.io/llm-measurement/charts/otelcol-genai-sketches`, version
  `0.3.3`. The chart and image versions are independent.
- Use the release's digest and attestations to verify artifacts before deployment.
- Connector counter arithmetic and summary wire formats are unchanged. In-memory
  windows restart when the collector restarts; compare retained files using the
  identity guidance below.
- This build also includes the already-merged Collector v0.162.0 / pdata v1.68.0
  update. Review its single-underscore Prometheus label naming change in
  [Upgrading](../UPGRADING.md) and check affected dashboard queries.

The distribution also updates `golang.org/x/text` from v0.41.0 to v0.42.0.
Its upstream NFC composition fix changes `text_v1` canonical bytes and keyed
identities for some supplementary-plane characters with combining marks,
including U+11F41 followed by U+0300 or U+0301. Upgrade at a window boundary;
keep affected old and new windows separate for merges and comparisons, or
rebuild them from original inputs using one normalizer version/build and the
same hash secret. The accounting fingerprint does not identify this normalization
change, so operators must keep affected windows separate explicitly. Custom builds
depend on their resolved `x/text` version, not just the connector module's declared
minimum. See [Upgrading](../UPGRADING.md#text-identities-in-v031).

The release workflow verifies the chart's appVersion against the runtime tag
and refuses to overwrite an existing OCI chart version, including on failed-job
retries. If a run stops after publishing the chart, inspect and recover the
existing digest and attestations manually or use a new patch version; rerunning
publication will stop rather than overwrite the chart.

## Verification

Run `make test-integration VERSION=0.3.1`, then source-scan both modules and
the generated `dist` module with `govulncheck v1.6.0`, using Go 1.26.9.
Also scan the generated collector and license-tool binaries with
`govulncheck -mode=binary`. The v0.3.0 image is stripped, so its binary scan's
dependency matches were checked against the tagged source and matching module
versions before classifying reachable findings.
