# Collector v0.7.0 / Helm chart 0.7.0

Chart 0.7.0 isolates the collector by default. A NetworkPolicy admits OTLP only
from pods in the release namespace. Prometheus scrapers, shadow backends and
cross-namespace senders get access through explicit rules. Collector v0.7.0
refuses weak or published hash keys and identity-bearing metric labels, and
model-usage accounting no longer copies the summary window for each span.

## Changes

- **Default network isolation.** The chart allows same-namespace OTLP and cluster
  DNS. Metrics peers and backend egress are declared in values, and selected-peer
  presets and mTLS instructions are included. With NetworkPolicy enabled, the chart refuses to render a
  shadow backend without an egress rule, or a ServiceMonitor without metrics
  peers or explicit ingress. Missing allowances fail at install.
- **Stronger identity defaults** ([#114](https://github.com/llm-measurement/otelcol-genai-sketches/pull/114)).
  Hash keys need at least 32 bytes, and the repository's example keys are
  refused. User, session, request, response, prompt and document identities
  can't be raw metric labels, including custom deduplication sources.
- **Bounded accounting work** ([#113](https://github.com/llm-measurement/otelcol-genai-sketches/pull/113)).
  Model-usage accounting precomputes its capacity instead of copying the summary
  window for each span. The optional Bloom deduplicator stops inserting at a
  per-window insertion cap and counts subsequent requests in
  `gen_ai_sketch_dedup_overflow_total`. Summary wire fields are unchanged.
- **Semantic-convention guidance** ([#115](https://github.com/llm-measurement/otelcol-genai-sketches/pull/115)).
  The docs mark legacy token-name aliases, which are still accepted.

## Breaking Changes

- **Hash keys.** Startup refuses a key shorter than 32 bytes or one of the
  repository's example keys. A private key that already meets the rule keeps its
  identities and output. Otherwise, generate a new key with `openssl rand -hex 32`
  and start a new comparison period at a window boundary. See
  [Upgrading](../UPGRADING.md#hash-key-and-label-hardening-in-v070).
- **Identity labels.** Configurations that map a user, session, request,
  response, prompt or document identity to a slice label are refused. Use model,
  team or route dimensions instead.
- **NetworkPolicy on by default.** A plain `helm upgrade` applies it, and
  senders outside the release namespace are blocked until you add rules.
  Upgrading with `--reuse-values` keeps an existing release's previous,
  policy-free values. Your cluster needs a network plugin that enforces
  NetworkPolicy. To opt out, set `networkPolicy.enabled: false`. See the
  [migration guide](../DEPLOYMENT.md#chart-070-network-policy-migration).

## Tested

The chart's network policy was tested on a two-node kind cluster with Calico on
linux/arm64. The tests covered allowed and blocked OTLP over HTTP and gRPC, DNS
egress, metrics scraping, shadow forwarding, and both upgrade paths.

## Install

Select collector v0.7.0 with chart 0.7.0. Then verify the image and chart
digests, signatures, checksums, SBOMs and provenance, as described in
[Deployment](../DEPLOYMENT.md#verify-an-image). Chart 0.7.0 pulls the image by
its `0.7.0` tag. Chart 0.7.1 follows with that image pinned by digest. To pin
now, set `image.digest` to the index digest in this release's
`image-digest.txt`.
