# Collector v0.7.0

Account for GenAI requests and tokens with bounded metrics and optional summaries,
while rejecting weak hash keys and unsafe identity labels. The companion chart
0.7.0 adds default network isolation, explicit sender and backend allow-lists,
and hardened pod settings.

Draft for release review; not a publication announcement. The runtime release
publishes the multi-architecture image and chart 0.7.0 together. A later chart
0.7.1 pins the image index from the verified release artifacts.

## Breaking Changes

- **Private hash keys must contain at least 32 bytes** ([#114](https://github.com/llm-measurement/otelcol-genai-sketches/pull/114)).
  Startup also rejects published example keys. Existing private keys meeting the
  requirement retain their identities. Replace a short or public key at a window
  boundary and start a new comparison period; see the
  [hash-key migration](../UPGRADING.md#hash-key-and-label-hardening-unreleased).
  Raw known user, session, request, response, prompt and document identities are
  not allowed as slice labels, including mapped and custom deduplication sources.
- **Chart 0.7.0 enables NetworkPolicy by default.** A plain upgrade blocks
  non-peer senders; the default OTLP peers are pods in the release namespace.
  Metrics peers and non-DNS backend egress need explicit rules. Upgrading an old
  release with `--reuse-values` retains its prior disabled-policy behavior;
  inspect the effective values before relying on isolation. For a deliberate
  opt-out, set `networkPolicy.enabled: false` in your
  [values](../../deploy/helm/otelcol-genai-sketches/values.yaml), as described in
  the [migration guide](../DEPLOYMENT.md#chart-070-network-policy-migration).
  A NetworkPolicy-enforcing network plugin is required.

## Compatibility And Installation

The release preparation retains the qualified collector's Go implementation and
module inputs. Qualification is not a claim that every instrumentation source
uses the same accounting contract; retain the configured profile and comparison
boundaries when upgrading.

After publication, verify the multi-architecture image index, platform digests,
signatures, attestations, checksums, SBOMs and OpenVEX evidence using
[Deployment](../DEPLOYMENT.md). Install the companion
[chart 0.7.0](chart-v0.7.0.md) uses `:0.7.0` from `appVersion` by default:
`image.tag` and `image.digest` are empty, following the v0.6.2 release pattern.
The image tag is mutable; supply the verified index digest explicitly when an
immutable image selection is required. The subsequent
[chart 0.7.1](chart-v0.7.1.md) will pin that same index by default through the
separate chart release workflow. README and Deployment pin updates follow both
publications in a reviewed PR; neither release changes their pins implicitly.
