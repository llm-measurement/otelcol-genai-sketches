# Collector v0.6.1 and Helm Chart 0.6.1

October 18, 2026 (Eastern Time). Keep valid span accounting available when
another sender submits malformed identities or extreme token values. Upgrade
the collector and chart together to 0.6.1.

## What You Get

- **Invalid input no longer blocks valid peers.** Malformed identities reject
  only the affected span, with fixed rejection reasons. Token fields above
  1,000,000,000 count as invalid, missing usage; the request and other valid
  fields remain counted.
- **Counter exhaustion is explicit.** Counters saturate instead of rejecting
  future batches. Exhausted summary windows and ranking bounds are unavailable,
  rather than exported as exact values. Previous valid summary files remain
  intact, and a healthy new window can export normally.
- **Accounting does not request replay after committing.** All batches use the
  transactional path. A downstream metric-delivery failure produces a fixed
  warning without asking the trace sender to resend already-counted spans.
- **Normal-input behavior stays unchanged.** Existing identity contracts,
  summary formats, model-usage profiles and deployment defaults are preserved.

## Upgrade

Deploy collector v0.6.1 or chart 0.6.1 with appVersion 0.6.1. Standalone builds
should use connector module v0.6.1. See [deployment verification](../DEPLOYMENT.md)
and [accounting diagnostics](../ACCOUNTING.md). The runtime release publishes
and signs the image and chart together through
`release.yml@refs/tags/v0.6.1`; no separate chart tag is needed.

## Limits

The fixed plausibility cap intentionally changes handling of extreme values
that earlier versions accepted; mixed-version equivalence is not claimed for
those inputs. Downstream delivery is not a durable queue: later cumulative
counters can recover counts, but missed gauges may not be recovered. Collector
stability remains alpha. Restrict receiver access and pin exact versions and
image digests.
