# v0.3.0 Release Notes

v0.3.0 ranks the users and sessions carrying the most reported tokens or model
attempts, as keyed hashes in logs and summary files.

## What Changes

- Rank hashed users or sessions, as well as prompts, with `topk_keys`. Choose
  reported tokens or model attempts as the weight. Rankings stay in structured
  logs and optional summary files, never in metric labels.
- Investigate high-share sessions even when token usage is missing by selecting
  request weighting. A request here is a counted model attempt, not an agent run.
- Reject invalid spans before changing counters, sketches, or evicting a slice
  when a destination would exceed its numeric limits.
- Preserve valid cache-read and reasoning-token subsets in the opt-in LiteLLM
  callback. Subsets are not added to input/output totals a second time.
- Report the connector's module version in component inventory and metric scope.

## Try The New Rankings

Keep the existing receivers, pipelines, secret, and summary-export settings. Add
this to the `genaisketch` connector configuration:

```yaml
topk: 20
topk_keys:
  - field: prompt_key
  - field: user_key
    weight: tokens
  - field: session_key
    weight: requests
```

The default session sources are `gen_ai.conversation.id` and `session.id`, not
`mcp.session.id`. The default user sources include `enduser.id` and `user.id`.
Missing identities are not invented. Shares describe attributed sketch weight,
not all traffic. See [Top-K Keys](../TOPK_KEYS.md) for extraction and limits.

## Before Upgrading

**Remove `session.id` and `gen_ai.conversation.id` from metric slices.** They now
overlap the default sensitive session field and fail validation even with `topk: 0`.
Validate the full configuration with the candidate binary before rollout.

Use fleetdiff v0.3.0 or later for user/session questions. Default export bytes and
the base accounting fingerprint are unchanged. Missing optional rankings produce
unknown answers, not zeros. Separate extraction markers reject incompatible
rankings. Collect complete new windows after enabling a field; historical files
cannot supply a field that was never collected.

Extra keys cost state per slice and retained window. Review [Sizing](../SIZING.md).
Restarts and rollbacks reset in-memory state. A rollback to v0.2.0 also requires
removing `topk_keys`; see [Upgrading](../UPGRADING.md).

The distribution and standalone connector module both target v0.3.0. The upstream
Collector remains v0.161.0 / pdata v1.67.0, and component stability remains Alpha.
Use the results to choose an investigation; see [Acting On Results](../TOKEN_USAGE.md#acting-on-results).

## Verification

Source checks cover default-byte compatibility, extraction-contract matching,
counter atomicity, and privacy. `TestSessionTopKPrivateSummaryPipeline` sends real
OTLP spans, checks user/session bounds, and scans metrics, logs, summary JSON, and
decoded sketch payloads for raw identifiers. `FLEETDIFF_BIN` adds a cross-repository
report check. PR checks run that pipeline against the production image before
merge. The release's `public-install` job runs the summary and top-k tests
against each signed Linux amd64/arm64 image by its platform digest.

```sh
make dist VERSION=0.3.0
FLEETDIFF_BIN=/path/to/fleetdiff go test -tags integration ./integration \
  -run '^TestSessionTopKPrivateSummaryPipeline$' -count=1 -v
```

Image/chart signatures, dependency inventories, provenance, and checksums are
verified separately as described in [Deployment](../DEPLOYMENT.md). Validate usage
coverage on your instrumentation before rollout.
