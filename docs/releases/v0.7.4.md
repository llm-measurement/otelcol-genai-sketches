# Security fix: updates the OpenTelemetry Go SDK

Collector v0.7.4 is a patch release with no configuration, accounting or default changes from v0.7.3.

## Dependency Fix

- `go.opentelemetry.io/otel`, `trace`, `metric`, `log`, `sdk`, `sdk/metric`
  and `sdk/log` move together to v1.47.0, which addresses CVE-2026-128085 /
  [GO-2026-6974](https://pkg.go.dev/vuln/GO-2026-6974). This is the first stable
  release of the Logs API (`log`) and SDK (`sdk/log`).

Both v0.7.3 Linux binaries contain the affected attribute-truncation code.
The source reachability scan lists paths through Collector internal telemetry.
These are advisory and scan findings, not a claim of demonstrated exploitation.

The existing Collector component versions and Go 1.26.11 are retained.

## Runtime Image

The runtime image moves to digest-pinned
`gcr.io/distroless/static-debian13:nonroot` because the Debian 12 image is no
longer updated. The collector binary remains statically linked, runs as user
and group 65532 and uses the same entrypoint. The image includes current
`tzdata` and `ca-certificates` packages.

## Release Evidence

The normal `release.yml` workflow builds the multi-architecture image and
publishes image signatures, attested `SHA256SUMS`, the SBOM index and OpenVEX
evidence. Verify the exact release tag, source commit, image digest, signing
identity and attestation subjects.

The runtime release includes intermediate chart 0.7.5-rc.1 with appVersion 0.7.4.
Stable chart 0.7.5 follows after the image exists, pins its multi-architecture
index digest and uses the separate `chart-release.yml` signing identity.

Independent signature, attestation, digest and outsider-install verification
precedes changes to README or site version pointers.
